# F3 — stochastic BM1 control with an explicit control-problem contract

This note begins the F3 implementation. F1 supplies the deterministic BM1
model/feasibility work and F2 supplies the stochastic SDE, finite-volume and
mixture distribution solvers plus the first stochastic objective/optimization
experiments. F3 turns those ingredients into a reusable control workflow.

F3 does **not** estimate model parameters. During F3 the parameter set and
initial law are supplied explicitly. Later F4 work may estimate those inputs
and then pass them into the same F3 interface without rewriting the control
solver.

## F3-A — common problem contract

### Purpose

The first step separates four concepts that had previously been assembled
inside individual experiment scripts:

1. model quantities that are held fixed during one control problem;
2. the physical initial distribution;
3. the price parametrization and optional fixed external price history;
4. numerical resolution.

This separation is deliberately small. It is not a new BM1 model and it does
not replace the existing F1/F2 evaluators.

The reusable implementation is

src/control/bm_1.py.

It defines:

- BM1Parameters: the known response functions and (C, k, Xi, sigma_x);
- BM1ControlNumerics: FV/objective resolution;
- BM1ControlProblem: baseline, target, horizon, price intervals, initial law,
  optional additional breakpoints and an optional fixed external price vector.

No shared package initializer, WM source, BM1 equation or generic solver is
changed.

### Fixed external prices versus decision prices

A central F3/F4 distinction is made explicit.

For a supplied external history, such as a historical spot-price signal,

\[
U(t)=U^{\mathrm{obs}}(t)
\]

is fixed. BM1ControlProblem.evaluate_observed(...) evaluates exactly that
price vector; it does not call an optimizer and does not overwrite the stored
prices.

For an open-loop control problem the decision is instead

\[
\boldsymbol u=(u_0,\ldots,u_{N-1})\in[0,1]^N,
\]

and the existing stochastic evaluator constructs the piecewise-constant
candidate U(t) from that vector. The problem contract returns that evaluator
through build_evaluator(...); existing optimizers can then act on it.

The parameter template deliberately contains a neutral placeholder price
rather than the observed price history. Candidate prices are therefore always
supplied explicitly by the evaluator/optimizer.

### Known model parameters

For state response f, price response g, flexibility Xi, capacity parameter C,
steepness k and process-noise intensity sigma_X, F3 still uses

\[
dX_t=
\frac{D(X_t,U(t),B(t))-B(t)}{C}\,dt
+\sigma_X X_t(1-X_t)\,dW_t.
\]

BM1Parameters only packages these already-existing quantities. It validates
the basic scalar domains needed by the current BM1 convention. It performs no
parameter fitting.

This design is intentional: when F4 later produces an estimate
\(\widehat\theta\), the control layer should only need a new BM1Parameters
instance.

### Initial law is independent of FV resolution

The physical initial distribution must not be identified with one particular
cell grid. BM1ControlProblem therefore stores an initial_mass_builder rather
than one fixed probability vector.

Given FV edges

\[
0=e_0<e_1<\cdots<e_M=1,
\]

the builder returns

\[
m_i(0)=P(e_i\le X_0<e_{i+1}),
\qquad
m_i(0)\ge0,\qquad
\sum_i m_i(0)=1.
\]

Consequently F3-B can change the number of FV cells while keeping the same
physical initial law. The F3-A reference continues to use the established
Beta(20,20) law from F2.

### Physical problem versus numerical resolution

BM1ControlNumerics currently contains

- number of FV state cells;
- maximum objective quadrature step;
- maximum FV integration step;
- the small BM model output-grid size needed to construct the wrapper model.

Changing these settings does not change the supplied baseline, target, price
edges, parameter values or initial-law builder.

This distinction is required for the F3-B refinement study.

### First controlled regression case

`build_f3_a_problem` in `src/validation/bm_1/control.py` reconstructs the
existing two-price stochastic reference through the new contract.

By default it only evaluates the attached fixed price vector. Thus the first
F3 executable demonstrates that fixed external prices can flow through the
same stochastic BM1 computation without being optimized.

Run

```powershell
python -B -m src.exe.run_model.bm_1.optimize contract
```

To additionally demonstrate that the same problem object can supply a decision
evaluator to the existing bounded Powell optimizer, run

```powershell
python -B -m src.exe.run_model.bm_1.optimize contract --optimize
```

The optional optimization is only an interface demonstration. The full
numerical/optimality analysis remains later F3 work.

### Tests

tests/test_bm1_control.py checks that:

- the new reference-FV route reproduces the existing two-price evaluator;
- the fast and reference FV paths agree tightly on the same fixed-price case;
- caller-owned price/grid arrays are copied;
- the observed price history is not inserted into the decision-price template;
- an observed-price evaluation fails explicitly when no observed path exists;
- the initial law is rebuilt when the FV spatial resolution changes;
- malformed problem/numerical inputs fail before a solver is entered.

These tests are regressions for the F3-A interface. They are not an
independent validation of the Fokker–Planck discretization; that is the purpose
of F3-B.

## What F3-A deliberately does not do

F3-A does not:

- fit (C, k, Xi, sigma_x) or response functions;
- claim that a spot price is necessarily the exact tariff seen by a consumer;
- define the final F3 terminal or price-smoothing terms;
- establish FV/MC discretization accuracy;
- optimize using real demand observations as if they were causal outcomes of a
  hypothetical alternative price;
- add feedback/MPC or per-path controls.

Those are separate questions.

## Handoff to later F3 steps

F3-B can now refine BM1ControlNumerics while holding the physical problem
fixed.

F3-C can extend the control objective without changing how model inputs and
fixed external prices enter.

F3-D uses the common problem for deterministic/stochastic decision
cross-evaluation. F3-E can then isolate initial-state and process uncertainty
without changing the control interface.

F3-F puts the dynamic-mixture evaluator behind the same control-problem
contract and compares the resulting decision with the FV reference.

F3-G can attach imported historical spot-price vectors as observed_prices and
run them through the fixed-price path. Parameter estimation remains F4; once
estimates exist, they should feed back through BM1Parameters rather than
creating a second control implementation.


## F3-B — numerical reference before further control conclusions

### Question

F3-B asks a numerical question before F3 changes the control objective or
draws stronger conclusions from optimized prices:

\[
\text{How much of a reported change in }J
\text{ comes from the price decision, and how much from discretization?}
\]

The candidate price vectors are therefore frozen.  F3-B does **not** optimize
again when the grid or time step changes.

The controlled candidate set is:

- the deterministic reference \([0.72,0.28]\);
- the F3-A stochastic candidate \([0.730609,0.264415]\);
- the neutral price \([0.5,0.5]\).

The F3-A candidate is a fixed numerical test vector, not a claim of a proven
global optimum.

### Error sources are separated

Write the computed tracking objective schematically as

\[
J_{N_x,h,q}(\boldsymbol u),
\]

where \(N_x\) is the number of FV cells, \(h\) is the maximum FV integration
step, and \(q\) is the objective quadrature resolution.

F3-B changes these one at a time:

1. spatial refinement changes \(N_x\) while \(h\) and \(q\) stay fixed;
2. FV time refinement changes \(h\) while \(N_x\) and \(q\) stay fixed;
3. quadrature refinement changes \(q\) while using one common propagated FV
   state distribution for every quadrature rule.

The last point matters because the existing evaluator embeds requested
objective output times in the solver grid.  If a new quadrature grid were
allowed to trigger a new propagation, a measured difference would mix
quadrature error and time-integration error.  The F3-B common-grid calculation
instead propagates once at the union of all requested quadrature midpoints and
then evaluates every quadrature rule from that same state history.

No Richardson extrapolation or formal asymptotic order is claimed.  The study
is an empirical refinement check for the actual F3 calculation.

### FV refinement quantities

For every fixed candidate, the script records

\[
J=J_{\mathrm{bias}}+J_{\mathrm{variance}},
\]

the FV probability-mass error, the minimum cell mass, the number of FV time
steps, and the change relative to the finest level in that sweep.

The provisional high-resolution FV reevaluation uses

\[
N_x=801,\qquad
q=\frac1{192}\text{ day},\qquad
h=\frac1{384}\text{ day}.
\]

This is a **reference setting for comparison**, not automatically the grid
that every later optimizer must use.  After the local F3-B results are known,
a cheaper working resolution may be selected if its numerical change is small
relative to the price-decision effect we need to distinguish.

A useful scale is

\[
\Delta J_{\mathrm{decision}}
=
\left|
J(\boldsymbol u_{\mathrm{det}})
-
J(\boldsymbol u_{\mathrm{F3A}})
\right|.
\]

The script reports two complementary diagnostics.  First, the final change in
the absolute stochastic-candidate objective is divided by this scale.  This is
a conservative check on the accuracy of the objective itself.  Second, it
tracks the decision gap

\[
G_h = J_h(\boldsymbol u_{\mathrm{det}})
      -J_h(\boldsymbol u_{\mathrm{F3A}})
\]

and reports the change in \(G_h\) between the two finest levels.  Shared
discretization error can cancel strongly in a policy comparison even when each
absolute objective is still moving.  Both quantities matter: the first for an
absolute numerical reference, the second for the specific claim that one
fixed policy improves on another.  Neither ratio is a proof of convergence.

### Monte Carlo comparison

The optional MC check estimates

\[
\widehat J_N
=
\frac1N\sum_{r=1}^N J^{(r)},
\]

with pathwise standard error

\[
\operatorname{SE}(\widehat J_N)
=
\frac{s_J}{\sqrt N}.
\]

All candidate policies use the same sampled initial states and the same Wiener
increments.  This common-random-number construction makes paired differences

\[
\widehat{\Delta J}
=
\frac1N\sum_{r=1}^N
\left(J^{(r)}_{\mathrm{reference}}
-
J^{(r)}_{\mathrm{candidate}}\right)
\]

much more informative than subtracting two independently noisy MC estimates.

The final MC comparison also reports prefixes of one shared path ensemble, so
\(N=1000,5000,10000,\ldots\) can be compared without changing the underlying
random stream.

### Coupled Euler-Maruyama time refinement

The optional EM time study uses one finest Brownian path and constructs every
coarser increment by summation,

\[
\Delta W^{\mathrm{coarse}}_j
=
\sum_{k\in I_j}
\Delta W^{\mathrm{fine}}_k.
\]

The generic EM grid builder guarantees a maximum step and embeds requested
output times, but it does not guarantee that independently built grids for
(h,h/2,h/4,\ldots) are nested.  F3-B therefore constructs an explicit family
of nested BM-only integration grids for this convergence experiment.  Every
coarser grid is an exact subset of the finest grid, while every requested
output time and input breakpoint remains a grid point and each level respects
its requested maximum step.  The shared EM solver itself is unchanged.

The coarse and fine simulations are then pathwise coupled.  For each fixed
price vector the script records:

- the MC objective;
- the paired path-cost difference to the finest EM level;
- the SE of that paired difference;
- the RMS terminal-state difference to the finest level;
- raw proposals outside \([0,1]\).

This tests EM time-step sensitivity without confusing it with independent
Monte Carlo sampling noise.

### Implementation

The reference executable is `src/exe/run_model/bm_1/refine.py`.
Its numerical calculations live in `src/validation/bm_1/numerics.py`.

The quick FV-only study is

```powershell
python -B -m src.exe.run_model.bm_1.refine
```

Monte Carlo is opt-in because it is substantially more expensive:

```powershell
python -B -m src.exe.run_model.bm_1.refine --mc-paths 20000
```

The coupled EM time study is independently opt-in:

```powershell
python -B -m src.exe.run_model.bm_1.refine --mc-time-paths 5000
```

Add `--verbose` for the full refinement tables. Add `--save` only when the run
should write JSON and a convergence figure under ignored `files/output/bm_1/runs/f3_b/`.
Use `--output-dir files/output/bm_1/f3_b` as well to intentionally update retained evidence.  Ordinary smoke tests leave the working tree unchanged.

### F3-B completion criterion

F3-B is ready to close when the local runs allow us to choose a working FV
resolution for later F3 steps and when the important candidate differences
are larger than the remaining measured numerical changes/MC uncertainty at
the chosen reference settings.

If FV and MC retain a material discrepancy that is many MC standard errors
wide under refinement, the discrepancy must be investigated before F3 uses
that comparison as strong quantitative evidence.

## F3-C — augmented control objective

### Purpose

F3-C extends the already verified stochastic tracking problem; it does not add
a new BM equation, density solver or optimizer. For a held price vector

\[
\boldsymbol u=(u_0,\ldots,u_{N-1}),
\]

define

\[
J_{\mathrm{F3C}}(\boldsymbol u)
=
J_{\mathrm{tracking}}(\boldsymbol u)
+
\lambda_T\,\mathbb E[(X_T-x_{\mathrm{ref}})^2]
+
\lambda_U\sum_{j=1}^{N-1}(u_j-u_{j-1})^2,
\]

with

\[
J_{\mathrm{tracking}}
=
\int_0^T \mathbb E[(D_t-A(t))^2]\,dt.
\]

The terminal term discourages an optimizer from obtaining a good tracking
score by ending with an arbitrarily depleted or charged flexibility state.
The price term discourages large jumps between adjacent held prices.

The terminal penalty is the expected squared deviation, not merely a penalty
on the terminal mean:

\[
\mathbb E[(X_T-x_{\mathrm{ref}})^2]
=
(\mathbb E[X_T]-x_{\mathrm{ref}})^2
+
\operatorname{Var}(X_T).
\]

Thus it penalizes both a shifted terminal mean and terminal uncertainty. A
mean-only penalty would define a different control problem.

### Numerical evaluation

For FV cell centers \(x_i\) and terminal cell probabilities \(m_i(T)\),

\[
\mathbb E[(X_T-x_{\mathrm{ref}})^2]
\approx
\sum_i (x_i-x_{\mathrm{ref}})^2m_i(T).
\]

The fast FV path already carries the terminal probability vector, so the
terminal term adds no second propagation and does not require storing the full
density history during optimization. The dynamic Beta-mixture evaluator uses
the terminal projected cell masses in the same expression.

For Monte Carlo,

\[
\widehat M_T
=
\frac1M\sum_{r=1}^M (X_T^{(r)}-x_{\mathrm{ref}})^2.
\]

The complete MC path cost contains the tracking integral, the pathwise terminal
term and the deterministic price-jump term. Paired MC comparisons therefore
use complete path costs, so covariance between tracking error and terminal
state is retained in the standard error.

The price regularizer

\[
R_U(\boldsymbol u)
=
\sum_{j=1}^{N-1}(u_j-u_{j-1})^2
\]

is a penalty on discrete price jumps. It is not claimed to approximate
\(\int |\dot U|^2\,dt\). This distinction matters if different price-grid
resolutions are compared: \(\lambda_U\) is tied to the chosen discrete price
parameterization unless an additional grid scaling is introduced and justified.

If the tracking integral carries a physical time unit, the raw terminal and
price-jump quantities are dimensionless. Consequently \(\lambda_T\) and
\(\lambda_U\) have the same units as \(J_{\mathrm{tracking}}\) (time under
the present normalized-power convention). No nonzero values are hard-coded as
physically correct weights.

### Backward consistency

Setting

\[
\lambda_T=\lambda_U=0
\]

recovers the established F3-A/B objective exactly. The forward BM dynamics,
FV propagation and tracking bias/variance calculation are unchanged; the new
terms are added only after the candidate trajectory/distribution has been
computed.

The default reference state is

\[
x_{\mathrm{ref}}=0.5,
\]

which matches the mean of the current Beta(20,20) reference initial law, but it
is an explicit control setting and can be changed.

The verified zero-weight regression gives the same candidate as F3-A,

\[
\boldsymbol u_{\mathrm{F3A}}
=
[0.730609,\;0.264415],
\qquad
J=6.79543131\times10^{-3}.
\]

### Weight sensitivity

A weight sweep is necessary before assigning substantive meaning to any
nonzero \(\lambda_T\) or \(\lambda_U\). Different weights define different
objectives, so the weighted total \(J_{\mathrm{F3C}}\) must not be ranked
directly across rows with different weights. Cross-weight comparisons instead
use the common raw quantities

\[
J_{\mathrm{tracking}},
\qquad
M_T=\mathbb E[(X_T-x_{\mathrm{ref}})^2],
\qquad
R_U=\sum_{j=1}^{N-1}(u_j-u_{j-1})^2,
\qquad
\boldsymbol u^*.
\]

The first sensitivity pass varies one weight at a time:

\[
\lambda_T\in
\{0,10^{-3},10^{-2},10^{-1},0.5\},
\qquad
\lambda_U=0,
\]

and

\[
\lambda_U\in
\{0,10^{-4},10^{-3},10^{-2},10^{-1}\},
\qquad
\lambda_T=0.
\]

These ranges deliberately span weak to dominating penalties. In the current
reference problem the terminal MSE is of order \(10^{-2}\), price roughness is
of order \(10^{-1}\), and the F3-A/B decision effect is of order \(10^{-4}\).
Hence \(\lambda_T\approx10^{-2}\) and
\(\lambda_U\approx10^{-3}\) already put the weighted penalties on roughly the
same numerical scale as the previously observed decision improvement.

Every weight pair is optimized independently from the same three starting
price vectors: the fixed reference, the established initial guess, and the
neutral price vector. A neighboring weight's optimum is not used as a warm
start. This avoids making the sweep depend on the order in which the weights
are visited. It does not turn the nonlinear Powell search into a proof of a
global optimum.

For exact global minimizers of \(f(u)+\lambda g(u)\), increasing
\(\lambda\) cannot increase the optimized raw penalty \(g\). Indeed, if
\(\lambda_2>\lambda_1\) and \(u_1,u_2\) are global minimizers, adding the
two optimality inequalities gives
\((\lambda_2-\lambda_1)(g(u_2)-g(u_1))\le0\). The corresponding unweighted
tracking term cannot improve at the same time. This gives a useful diagnostic
for each one-dimensional sweep: material violations of the expected trade-off
can indicate local-optimizer or tolerance effects, but the code does not impose
monotonicity artificially.

After the one-dimensional sweeps have been interpreted, the Cartesian product
of the same weight sets can be run as an optional two-dimensional grid. The
grid is useful for locating trade-off regions, but it still does not identify
a unique mathematically preferred weight pair without an external criterion
for how much terminal restoration or price smoothness is worth relative to
tracking error.

### Observed reference sensitivity

The local reference sweep on the verified F3-C implementation gives the
expected monotone one-dimensional trade-offs. With \(\lambda_U=0\),

| \(\lambda_T\) | \(J_{\mathrm{tracking}}\) | terminal MSE | roughness |
|---:|---:|---:|---:|
| 0 | \(6.79543131\times10^{-3}\) | \(1.43596257\times10^{-2}\) | \(2.17337214\times10^{-1}\) |
| \(10^{-2}\) | \(6.79610938\times10^{-3}\) | \(1.42189059\times10^{-2}\) | \(2.17901659\times10^{-1}\) |
| \(3\times10^{-2}\) | \(6.80077532\times10^{-3}\) | \(1.39614226\times10^{-2}\) | \(2.17724844\times10^{-1}\) |
| \(10^{-1}\) | \(6.85267738\times10^{-3}\) | \(1.31463073\times10^{-2}\) | \(2.18674408\times10^{-1}\) |

Thus \(\lambda_T=0.1\) reduces terminal MSE by about \(8.45\%\) relative to
the unregularized optimum while increasing raw tracking cost by about
\(0.84\%\). The smaller \(\lambda_T=0.03\) gives about \(2.76\%\) lower
terminal MSE for about \(0.08\%\) higher tracking cost.

With \(\lambda_T=0\),

| \(\lambda_U\) | \(J_{\mathrm{tracking}}\) | terminal MSE | roughness |
|---:|---:|---:|---:|
| 0 | \(6.79543131\times10^{-3}\) | \(1.43596257\times10^{-2}\) | \(2.17337214\times10^{-1}\) |
| \(10^{-3}\) | \(6.79694971\times10^{-3}\) | \(1.43584294\times10^{-2}\) | \(2.14157512\times10^{-1}\) |
| \(3\times10^{-3}\) | \(6.81069017\times10^{-3}\) | \(1.43424656\times10^{-2}\) | \(2.07147330\times10^{-1}\) |
| \(10^{-2}\) | \(6.93628881\times10^{-3}\) | \(1.44072442\times10^{-2}\) | \(1.87141817\times10^{-1}\) |

Here \(\lambda_U=0.003\) reduces roughness by about \(4.69\%\) for about
\(0.22\%\) higher tracking cost, while \(\lambda_U=0.01\) reduces roughness
by about \(13.9\%\) for about \(2.07\%\) higher tracking cost.

A focused two-dimensional sweep over

\[
\lambda_T\in\{0,0.01,0.03,0.1\},
\qquad
\lambda_U\in\{0,0.001,0.003,0.01\}
\]

also preserves the expected monotone slice behavior. For example,

| \((\lambda_T,\lambda_U)\) | tracking change | terminal-MSE reduction | roughness reduction |
|---:|---:|---:|---:|
| \((0.03,0.003)\) | \(+0.29\%\) | \(2.43\%\) | \(4.65\%\) |
| \((0.10,0.003)\) | \(+0.99\%\) | \(8.02\%\) | \(4.34\%\) |
| \((0.03,0.010)\) | \(+2.17\%\) | \(2.36\%\) | \(13.93\%\) |
| \((0.10,0.010)\) | \(+2.95\%\) | \(7.85\%\) | \(14.08\%\) |

The tested region therefore contains no unique mathematically optimal weight
pair: the appropriate choice depends on how terminal restoration and price
smoothness are valued relative to tracking. For later experiments it is useful
to distinguish a light regularization region around
\((0.03,0.003)\), a terminal-emphasized region around
\((0.10,0.003)\), and a stronger smoothing region with
\(\lambda_U\approx0.01\). These are sensitivity landmarks, not fitted
parameters or universally preferred settings.

The existing files are extended rather than creating separate F3-C modules:

- `src/control/objective.py`: terminal MSE and price-jump mathematics;
- `src/control/bm_1.py`: objective settings and FV/mixture/MC evaluation;
- `src/validation/bm_1/control.py`: F3-C reference and sensitivity studies;
- `src/exe/run_model/bm_1/optimize.py`: reporting and command-line entry;
- existing objective/control tests cover the new terms and sensitivity-grid structure.

One chosen pair can be run with

```powershell
python -B -m src.exe.run_model.bm_1.optimize augmented --terminal-weight 0.01 --smoothing-weight 0.001
```

The default one-dimensional sensitivity sweeps are

```powershell
python -B -m src.exe.run_model.bm_1.optimize sensitivity
```

and the full Cartesian grid is opt-in:

```powershell
python -B -m src.exe.run_model.bm_1.optimize sensitivity --grid
```

`--terminal-weights` and `--smoothing-weights`.

The sensitivity calculation is an analysis of the F3-C objective, not a
calibration of economic preferences. Final weight selection must therefore be
reported as a modelling choice supported by the observed trade-offs rather
than as a parameter inferred from the BM equations themselves.

## F3-D — deterministic versus stochastic control decision

### Question

F3-D isolates the effect of using a stochastic state model in the control
decision. The baseline, target, BM response functions, physical parameters,
price intervals and objective definition are held fixed. Only the state model
used by the controller changes.

The deterministic counterpart uses

\[
X_0=0.5,
\qquad
\sigma_X=0,
\]

and therefore

\[
\dot X_t
=
\frac{D(X_t,U(t),B(t))-B(t)}{C}.
\]

The stochastic controller uses the established reference law

\[
X_0\sim\operatorname{Beta}(20,20),
\qquad
\sigma_X=0.5,
\]

and

\[
dX_t
=
\frac{D(X_t,U(t),B(t))-B(t)}{C}\,dt
+
\sigma_X X_t(1-X_t)\,dW_t.
\]

The deterministic initial state is explicit in the control problem rather than
being silently inferred from the stochastic initial distribution.

### Common objective and two optimized policies

For a fixed F3 objective, define

\[
\boldsymbol u_{\mathrm{det}}^*
=
\arg\min_{\boldsymbol u\in[0,1]^N}
J_{\mathrm{det}}(\boldsymbol u)
\]

and

\[
\boldsymbol u_{\mathrm{stoch}}^*
=
\arg\min_{\boldsymbol u\in[0,1]^N}
J_{\mathrm{stoch}}(\boldsymbol u).
\]

Both models use the same price parametrization and the same F3-C penalty
settings. In the deterministic model the demand variance is zero and the
terminal penalty is

\[
(X_T-x_{\mathrm{ref}})^2.
\]

In the stochastic model the corresponding quantities are the expected
tracking cost and

\[
\mathbb E[(X_T-x_{\mathrm{ref}})^2].
\]

F3-D first uses the unregularized objective
\(\lambda_T=\lambda_U=0\) so that stochasticity is the only modelling change.
The comparison is then repeated with the light F3-C landmark

\[
\lambda_T=0.03,
\qquad
\lambda_U=0.003
\]

as a robustness check. These weights remain modelling landmarks, not fitted
parameters.

### Cross-evaluation

Optimizing each model is not sufficient by itself. The two returned policies
are evaluated in both models:

| policy | deterministic model | stochastic model |
|---|---:|---:|
| \(\boldsymbol u_{\mathrm{det}}^*\) | \(J_{\mathrm{det}}(\boldsymbol u_{\mathrm{det}}^*)\) | \(J_{\mathrm{stoch}}(\boldsymbol u_{\mathrm{det}}^*)\) |
| \(\boldsymbol u_{\mathrm{stoch}}^*\) | \(J_{\mathrm{det}}(\boldsymbol u_{\mathrm{stoch}}^*)\) | \(J_{\mathrm{stoch}}(\boldsymbol u_{\mathrm{stoch}}^*)\) |

The main F3-D quantity is the stochastic value of using the stochastic-aware
decision,

\[
\Delta J_{\mathrm{stoch}}
=
J_{\mathrm{stoch}}(\boldsymbol u_{\mathrm{det}}^*)
-
J_{\mathrm{stoch}}(\boldsymbol u_{\mathrm{stoch}}^*).
\]

The deterministic cost of using the stochastic-aware policy is

\[
\Delta J_{\mathrm{det}}
=
J_{\mathrm{det}}(\boldsymbol u_{\mathrm{stoch}}^*)
-
J_{\mathrm{det}}(\boldsymbol u_{\mathrm{det}}^*).
\]

For exact global minima both quantities are non-negative. Small negative
values can arise from optimizer tolerances; material negative values require
investigation.

Policy displacement is also reported through

\[
\|\boldsymbol u_{\mathrm{stoch}}^*
-\boldsymbol u_{\mathrm{det}}^*\|_\infty
\]

and

\[
\|\boldsymbol u_{\mathrm{stoch}}^*
-\boldsymbol u_{\mathrm{det}}^*\|_2.
\]

### Monte Carlo validation

The stochastic cross-evaluation uses finite volume as the deterministic
objective supplied to Powell. After optimization, the two policies are also
compared with common-random-number Monte Carlo paths. For path \(r\),

\[
\Delta J^{(r)}
=
J^{(r)}(\boldsymbol u_{\mathrm{det}}^*)
-
J^{(r)}(\boldsymbol u_{\mathrm{stoch}}^*),
\]

and the paired standard error is

\[
\operatorname{SE}(\overline{\Delta J})
=
\frac{s_{\Delta J}}{\sqrt M}.
\]

This validates the policy difference without confusing it with the variance
of two independently simulated objective estimates.

### Observed reference comparison

The verified unregularized comparison gives

\[

## F3-E — isolating initial-state and process uncertainty

### Question

F3-D established that the optimal policy changes when the deterministic state
model is replaced by the full stochastic BM1 model. That comparison changed
two uncertainty sources at once:

\[
X_0=0.5
\quad\longrightarrow\quad
X_0\sim\operatorname{Beta}(20,20),
\]

and

\[
\sigma_X=0
\quad\longrightarrow\quad
\sigma_X=0.5.
\]

F3-E isolates these two changes. The reference study uses four models:

| scenario | initial state/law | \(\sigma_X\) |
|---|---|---:|
| deterministic | \(X_0=0.5\) | \(0\) |
| initial only | \(X_0\sim\operatorname{Beta}(20,20)\) | \(0\) |
| process only | \(X_0=0.5\) | \(0.5\) |
| full | \(X_0\sim\operatorname{Beta}(20,20)\) | \(0.5\) |

All other physical/control quantities are held fixed: \(B(t)\), \(A(t)\),
\(f\), \(g\), \(C\), \(k\), \(\Xi\), the two price intervals and the
optimizer starts. The three distribution-valued cases use the same 201-cell FV
grid and the same time/quadrature resolution; the deterministic case uses the
corresponding ODE evaluator from F3-D.

The first F3-E pass keeps

\[
\lambda_T=\lambda_U=0
\]

so that objective-weight choices from F3-C do not become another changing
factor.

### Four independently optimized policies

For each uncertainty scenario \(s\), define

\[
\boldsymbol u_s^*
=
\arg\min_{\boldsymbol u\in[0,1]^2}
J_s(\boldsymbol u).
\]

Every scenario is optimized independently from the same three starts used in
F3-A through F3-D. A neighboring uncertainty case is not used as a warm start.

The deterministic scenario uses the ODE evaluator from F3-D. The other three
scenarios use the established fast finite-volume evaluator.

For the process-only case the physical point initial condition is represented
on the FV grid by one cell carrying unit probability mass. At the reference
resolution of 201 cells, \(X_0=0.5\) is exactly the midpoint of that cell, so
the point-state benchmark is not shifted to a neighboring state value by the
discretization.

### Cross-evaluation and regret

The four optimized policies are evaluated in all four models. For model
scenario \(s\) and policy obtained from scenario \(q\), define

\[
J_s(\boldsymbol u_q^*).
\]

This gives a \(4\times4\) cross-evaluation matrix. Within one model row, the
regret of using another scenario's policy is

\[
R_{s\leftarrow q}
=
J_s(\boldsymbol u_q^*)
-
J_s(\boldsymbol u_s^*).
\]

For an exact global minimum,

\[
R_{s\leftarrow q}\ge0.
\]

Small negative values can arise from numerical optimization tolerance, while a
materially negative value would require investigation.

Objective levels from different model rows should not be interpreted as a
single ranking because the probability law defining each expectation changes.
The useful comparisons are policies within one fixed row.

The full-model row is particularly informative:

\[
R_{\mathrm{full}\leftarrow\mathrm{det}},
\qquad
R_{\mathrm{full}\leftarrow\mathrm{initial}},
\qquad
R_{\mathrm{full}\leftarrow\mathrm{process}}.
\]

These quantify the full stochastic cost of designing the controller while
ignoring both uncertainty sources, retaining only initial uncertainty, or
retaining only process uncertainty. They are not assumed to add linearly:
the BM dynamics and the optimization are nonlinear, so an interaction between
the two uncertainty sources is possible.

Policy displacement from the deterministic optimum is also reported through

\[
\|\boldsymbol u_s^*-\boldsymbol u_{\mathrm{det}}^*\|_\infty
\]

and

\[
\|\boldsymbol u_s^*-\boldsymbol u_{\mathrm{det}}^*\|_2.
\]

### Observed source decomposition

The verified reference optimization gives

| scenario | optimized prices |
|---|---|
| deterministic | \([0.720000,\;0.280000]\) |
| initial only | \([0.723277,\;0.275548]\) |
| process only | \([0.722198,\;0.267527]\) |
| full | \([0.730609,\;0.264415]\) |

The policy displacement from the deterministic optimum is

| scenario | \(L^\infty\) distance | \(L^2\) distance |
|---|---:|---:|
| initial only | \(4.451593\times10^{-3}\) | \(5.527705\times10^{-3}\) |
| process only | \(1.247348\times10^{-2}\) | \(1.266560\times10^{-2}\) |
| full | \(1.558514\times10^{-2}\) | \(1.885346\times10^{-2}\) |

Thus the process-noise-only policy moves substantially farther from the
deterministic decision than the initial-uncertainty-only policy.

The full-model cross-evaluation row is

\[
\begin{aligned}
J_{\mathrm{full}}(\boldsymbol u_{\mathrm{det}}^*)
&=6.92173938\times10^{-3},\\
J_{\mathrm{full}}(\boldsymbol u_{\mathrm{initial}}^*)
&=6.85864792\times10^{-3},\\
J_{\mathrm{full}}(\boldsymbol u_{\mathrm{process}}^*)
&=6.81222119\times10^{-3},\\
J_{\mathrm{full}}(\boldsymbol u_{\mathrm{full}}^*)
&=6.79543131\times10^{-3}.
\end{aligned}
\]

Relative to the deterministic policy in the full stochastic model, using the
initial-only policy lowers the objective by about \(0.91\%\), the process-only
policy by about \(1.58\%\), and the full policy by about \(1.82\%\).

Equivalently, the full-model regrets are

\[
R_{\mathrm{full}\leftarrow\mathrm{det}}
=1.263081\times10^{-4},
\]

\[
R_{\mathrm{full}\leftarrow\mathrm{initial}}
=6.321660\times10^{-5},
\]

and

\[
R_{\mathrm{full}\leftarrow\mathrm{process}}
=1.678988\times10^{-5}.
\]

Accounting for process noise alone therefore closes about \(86.7\%\) of the
full-model regret of the deterministic policy, whereas accounting for initial
uncertainty alone closes about \(50.0\%\). These percentages are descriptive
for this reference problem, not an additive variance decomposition: the two
uncertainty sources interact through the nonlinear dynamics and optimization.

Every row-wise regret in the \(4\times4\) cross-evaluation is non-negative,
and all four Powell optimizations succeed from all three starts. The source
decomposition is therefore numerically consistent with each scenario's own
reported optimum.

### Scope and implementation

F3-E does not yet sweep arbitrary values of \(\sigma_X\), change the Beta
shape parameters, or estimate uncertainty from data. The first step is a
controlled source decomposition using the established reference values. A
continuous sensitivity study is only useful after this four-case comparison
has shown which source drives the decision materially.

No new Python module is introduced. The implementation extends the existing
control/validation/CLI files. The generic control layer gains only the small
point-initial-law helper needed to represent a deterministic state on an FV
grid.

Run

```powershell
python -B -m src.exe.run_model.bm_1.optimize uncertainty
```

Use `--verbose` only when optimizer progress is needed.

## F3-F — FV versus dynamic-mixture control decisions

### Question

F2 established the dynamic Beta-mixture approximation and used it as a
secondary stochastic optimizer. F3-F asks a narrower control question:

\[
\text{Does the dynamic-mixture approximation lead to essentially the same
price decision as finite volume?}
\]

The physical control problem is held fixed at the established full stochastic
reference,

\[
X_0\sim\operatorname{Beta}(20,20),
\qquad
\sigma_X=0.5,
\]

with the same \(B(t)\), \(A(t)\), \(f\), \(g\), \(C\), \(k\), \(\Xi\), two
price intervals and optimizer starts. The first comparison keeps

\[
\lambda_T=\lambda_U=0
\]

so that objective regularization is not another changing factor.

### Common F3 problem contract

The dynamic-mixture evaluator is now constructed directly from
`BM1ControlProblem`, just like the deterministic and FV evaluators. In
conceptual form,

```python
fv_reference = problem.build_evaluator(reference_numerics, fast=True)
fv_design = problem.build_evaluator(design_numerics, fast=True)
mixture_design = problem.build_mixture_evaluator(
    design_numerics,
    degree=30,
    cfl=0.4,
)
```

All three evaluators therefore receive the same physical parameters, initial
law, price edges, target and F3 objective settings. The mixture implementation
remains the existing `DynamicMixturePriceEvaluator`; F3-F adds no
second mixture solver.

### Projection-solver robustness

**Historical scope.** The following records the original F3-F implementation
and its retained measurements. The post-F3-F maintenance candidate now uses a
prepared simplex-face least-squares solver, with an independently checked SLSQP
fallback, for BM dynamic projection. It does not change the physical problem.
See `BM_AUDIT_F1_F3.md` for both the old held-policy regression and the newly
optimized policy; small backend-dependent policy differences are reported
explicitly rather than replacing the historical numbers below.


The first local F3-F optimizer run exposed a numerical issue that the earlier
fixed-price mixture tests did not exercise. Powell can probe valid price
vectors far from the reference policies. For some of those candidates the
degree-30 Beta projection QP is sufficiently ill-conditioned that the custom
active-set iterations can stall even though the simplex-constrained convex
projection itself remains well defined.

The projection problem is still

\[
\min_{c\ge 0,\;\mathbf 1^T c=1}
\frac12\|Ac-b\|_2^2.
\]

F3-F therefore keeps the custom active-set solver as the primary projection
backend, but limits one projection attempt to a finite iteration budget. If
that numerical iteration stalls, the **same** least-squares problem with the
same simplex constraints is retried with SLSQP. This is a solver fallback, not
a change of mixture model or objective. No density clipping, coefficient
renormalization or altered target is introduced.

Every dynamic-mixture evaluation records the number of projection fallbacks.
Probability-mass, coefficient-sum and non-negativity checks remain mandatory
after either solver. The fallback exists so that an outer price optimizer can
evaluate valid candidate prices without turning a numerical active-set cycle
into an artificial hole in the control domain.

### Separating method error from design-grid error

Repeated mixture optimization is substantially more expensive than FV because
every internal explicit prediction is followed by a simplex-constrained
projection. F3-F therefore retains the reviewed F2-I mixture design setting

\[
M=30,\qquad N_x=81,\qquad \mathrm{CFL}=0.4.
\]

A direct comparison between an 81-cell mixture policy and a 201-cell FV policy
would mix two effects:

1. the numerical density method;
2. the spatial resolution used during optimization.

F3-F therefore optimizes **three** policies:

\[
\boldsymbol u_{\mathrm{FV},201}^*,
\qquad
\boldsymbol u_{\mathrm{FV},81}^*,
\qquad
\boldsymbol u_{\mathrm{mix},30,81}^*.
\]

The first is the established F3 FV reference. The second is an 81-cell FV
control using exactly the same design grid as the mixture. The third is the
degree-30 dynamic-mixture control on that same 81-cell grid.

Thus the comparison between
\(\boldsymbol u_{\mathrm{FV},81}^*\) and
\(\boldsymbol u_{\mathrm{mix},30,81}^*\) isolates the practical **method**
effect at a matched spatial resolution, while the comparison between the two
FV policies measures the **design-grid** effect.

All three optimizers start independently from the same three F3 reference
vectors. No optimizer is warm-started from another method's optimum.

The two FV searches use the established tight Powell settings. The mixture
search retains the reviewed F2-I tolerances because each outer evaluation
contains many constrained projection solves. Successful multistart termination
still produces numerical candidates, not a proof of global optimality.

### Design-grid diagnostics

On the common 81-cell design grid, two quantities should be non-negative for
exact global minima:

\[
R_{\mathrm{FV81}\leftarrow\mathrm{mix}}
=
J_{\mathrm{FV},81}(\boldsymbol u_{\mathrm{mix},30,81}^*)
-
J_{\mathrm{FV},81}(\boldsymbol u_{\mathrm{FV},81}^*),
\]

and

\[
R_{\mathrm{mix}\leftarrow\mathrm{FV81}}
=
J_{\mathrm{mix},30,81}(\boldsymbol u_{\mathrm{FV},81}^*)
-
J_{\mathrm{mix},30,81}(\boldsymbol u_{\mathrm{mix},30,81}^*).
\]

A material negative value would indicate optimizer/tolerance trouble and must
be investigated before interpreting the policy difference.

### Common 201-cell reevaluation

After the three policies are fixed, all of them are reevaluated using

\[
\text{FV}_{201},
\qquad
\text{mixture}_{30,201},
\qquad
\text{mixture}_{38,201}.
\]

The FV reference gives two useful regrets:

\[
R_{\mathrm{grid}}
=
J_{\mathrm{FV},201}(\boldsymbol u_{\mathrm{FV},81}^*)
-
J_{\mathrm{FV},201}(\boldsymbol u_{\mathrm{FV},201}^*),
\]

which measures the consequence of designing FV on the coarser 81-cell grid,
and

\[
R_{\mathrm{mix\ policy}}
=
J_{\mathrm{FV},201}(\boldsymbol u_{\mathrm{mix},30,81}^*)
-
J_{\mathrm{FV},201}(\boldsymbol u_{\mathrm{FV},201}^*),
\]

which measures the total reference-FV cost of using the mixture-designed
policy.

For the two 201-cell mixture references, F3-F reports signed differences
relative to the FV-201 policy. These are deliberately called differences, not
regrets: neither the 81-cell FV policy nor the 81-cell mixture policy is
claimed to minimize the 201-cell mixture objective, and the degree-38
evaluator is not optimized at all.

The degree-38 calculation is a held-policy robustness check. F2-G showed that
high-degree coefficient recovery can be poorly conditioned, so the represented
density/objective is more meaningful than interpreting tiny coefficient
changes.

Policy distances are reported for

\[
\boldsymbol u_{\mathrm{FV},81}^*
-\boldsymbol u_{\mathrm{FV},201}^*,
\]

\[
\boldsymbol u_{\mathrm{mix},30,81}^*
-\boldsymbol u_{\mathrm{FV},81}^*,
\]

and

\[
\boldsymbol u_{\mathrm{mix},30,81}^*
-\boldsymbol u_{\mathrm{FV},201}^*.
\]

This separates a grid-induced policy shift from the additional mixture-method
shift.

### Optional Monte Carlo check

After the policies are fixed, common-random-number Monte Carlo evaluates all
three under the same SDE paths. For candidate policy \(q\), the reported paired
difference is

\[
\widehat{\Delta J}_{q}
=
\frac1N\sum_{r=1}^N
\left[
J^{(r)}(\boldsymbol u_{\mathrm{FV},201}^*)
-
J^{(r)}(\boldsymbol u_q^*)
\right].
\]

A positive value means the candidate has lower MC cost than the FV-201 policy;
a negative value means the FV-201 policy has lower MC cost. The paired
standard error is reported with each difference. MC validates fixed decisions;
it is not part of any optimizer.

### Working-grid result and high-resolution follow-up

The first completed F3-F run gives

\[
u^*_{\mathrm{FV},201}=(0.730609,0.264415),
\quad
u^*_{\mathrm{FV},81}=(0.729329,0.263873),
\quad
u^*_{\mathrm{mix},30,81}=(0.735904,0.263610).
\]

On the 201-cell working FV evaluator, the mixture-designed policy has regret

\[
4.119395\times10^{-6},
\]

while the paired 20,000-path Monte Carlo calculation at the same working
time resolution reports FV-reference minus mixture

\[
-1.694220\times10^{-7}
\quad\text{with}\quad
\mathrm{SE}=7.596\times10^{-7}.
\]

The sign is consistent with FV weakly preferring its own policy, but the
magnitude is not consistent with treating the working-grid FV regret as an
accurate estimate of the true policy gap: the discrepancy is about 5.2 paired
MC standard errors.

This is not surprising on the scale being tested. F3-B already showed that
moving the coupled Euler--Maruyama maximum step from \(1/96\) to \(1/384\)
can change a paired policy gap by several \(10^{-6}\), which is the same order
as the complete F3-F policy regret. Therefore the inexpensive 201-cell,
\(1/96\)-day working setup is sufficient for designing the policies but not
for making the final quantitative claim that their costs differ by only a few
\(10^{-6}\).

F3-F consequently adds a **validation-only** command. It does not rerun the
expensive mixture optimization. It re-optimizes only the FV controller at the
established F3-B high-resolution settings

\[
N_x=801,\qquad
q=1/192,\qquad
h=1/384,
\]

then reevaluates the already-fixed FV-201, FV-81 and mixture policies against
that high-resolution FV optimum. It also runs common-random-number MC at the
same fine time/objective settings and, optionally, a coupled EM time
refinement. This extra step is required before F3-F is closed.

Using the policies printed by the control run:

```powershell
python -B -m src.exe.run_model.bm_1.optimize mixture-validate --fv-reference-prices 0.730609 0.264415 --fv-design-prices 0.729329 0.263873 --mixture-prices 0.735904 0.263610 --mc-paths 20000 --mc-time-paths 5000
```

The six-decimal policy values are sufficient for this validation check because
the rounding perturbation is orders of magnitude smaller than the observed
method/grid policy shifts; the retained conclusion should nevertheless report
them as rounded displayed policies rather than exact optimizer outputs.

### What the comparison does and does not isolate

The matched 81-cell comparison removes the spatial-grid difference between the
FV and mixture **design** problems, but the numerical methods still differ in
more than projection. The dynamic-mixture predictor uses an explicit
conservative flux with drift averaged from neighboring cell centers, whereas
the FV reference uses the implicit finite-volume discretization with face
drift evaluation. Therefore the remaining matched-grid policy gap is the
practical difference between the two complete numerical evaluators, not a pure
projection-error decomposition.

F3-F does not change the stochastic model, fit parameters, vary
\(\sigma_X\), increase the number of price intervals or introduce feedback.
Those are separate extensions.

No new Python module is introduced. The existing control, validation, CLI,
tests and notes are extended.

also differ in their actual integration grids, not only in finite sampling.

## F3-G — historical spot prices as fixed external input

### Question

F3-A--F3-F deliberately used controlled synthetic price problems so that model,
numerical and decision effects could be separated. F3-G is the first
data-backed integration step. Its narrow question is

\[
\text{Can an imported historical spot-price path be attached to the same F3
control problem and evaluated unchanged as an external input?}
\]

This is intentionally **not** parameter estimation. The BM parameters and
response functions remain the established reference values. F4 will address
whether those quantities should be estimated from data.

Historical DK1 spot prices are observations, not variables that the optimizer
may silently overwrite. `BM1ControlProblem` already encodes this distinction
through the immutable `observed_prices` field and
`problem.evaluate_observed(numerics)`. F3-G connects the existing
historical-data pipeline to that public contract instead of constructing a
separate FV evaluator directly inside the executable.

### One historical-day problem

For a selected day, the existing data preparation supplies 24 hourly values
for the observed normalized aggregate consumption used as the retrospective
target \(A(t)\), a history-only baseline \(B(t)\) obtained hour by hour from
the trimmed mean of the same weekday in the preceding five weeks, and the
observed normalized DK1 spot-price path.

The day is represented on

\[
T=[0,1],
\qquad
0=t_0<t_1<\cdots<t_{24}=1,
\]

with one right-continuous price value per hourly interval. The historical
problem uses the same `BM1ControlProblem` contract with hourly price edges,
the historical spot vector attached as `observed_prices`, and the hourly
edges also supplied as internal breakpoints.

The fixed model inputs remain

\[
f(x)=1-2x,\qquad g(u)=1-2u,
\qquad C=1,\qquad k=2,\qquad \Xi=1,
\qquad \sigma_X=0.5,
\]

with

\[
X_0\sim\operatorname{Beta}(20,20).
\]

These are reference assumptions carried into the historical pipeline. They
are **not** claimed to have been identified from the historical consumption
and price data.

`observed_prices` is copied and made read-only by the common control problem.
The neutral parameter template remains \(U=0.5\), so attaching an observed
price history cannot accidentally turn that history into the template used
for later candidates.

### Fixed-input path and optional retrospective optimization

The core F3-G calculation is

\[
J_{\mathrm{hist}}
=
J\!\left(\boldsymbol u_{\mathrm{spot}}\right),
\]

where the 24-vector \(\boldsymbol u_{\mathrm{spot}}\) is the imported,
normalized DK1 price history. No optimization is required.

A constant neutral vector

\[
\boldsymbol u_{0.5}=(0.5,\ldots,0.5)
\]

is retained as a simple fixed benchmark under exactly the same target,
baseline, initial law, parameters and numerical settings. This is a model
diagnostic, not a statement that one historical electricity-price regime
caused the observed demand.

The older historical executable also contains a 24-dimensional Powell
optimization. F3-G keeps that calculation available as a retrospective
oracle/check,

\[
\boldsymbol u_{\mathrm{oracle}}^*
=
\arg\min_{\boldsymbol u\in[0,1]^{24}}
J(\boldsymbol u; A_{\mathrm{observed}}),
\]

but it is explicitly secondary. The target day is already known when this
optimization is run. Therefore this policy is not a prospective tariff
recommendation and its improvement over the observed price path is not a
causal savings estimate.

For fixed-input mode, run

```powershell
python -B -m src.exe.run_model.bm_1.real_data --no-optimize --no-mc
```

and add common-random-number Monte Carlo by omitting `--no-mc`:

```powershell
python -B -m src.exe.run_model.bm_1.real_data --no-optimize
```

The previous retrospective oracle workflow remains available by omitting
`--no-optimize`.

When Monte Carlo is enabled, the fixed-input comparison also reports the paired
common-random-number difference

\[
\widehat{\Delta J}_{0.5-\mathrm{spot}}
=
\widehat J(\boldsymbol u_{0.5})
-
\widehat J(\boldsymbol u_{\mathrm{spot}}).
\]

A positive value therefore means the observed spot path has the lower MC cost;
a negative value means the neutral benchmark has the lower MC cost. This is a
paired model-objective comparison under shared simulated paths, not a causal
estimate of the effect of historical spot prices.

### Historical preprocessing and interpretation limits

Consumption and DK1 prices are normalized using the retained Jan--Oct 2022
season-wide minima and maxima. This keeps selected historical values inside
the normalized BM input domain for the retained season, but it uses
information from the complete retrospective season. It is therefore not a
prospective, deployment-safe normalization rule.

The five-week baseline itself is history-only relative to each target day:
only preceding same-weekday observations enter the trimmed hourly mean. The
target, however, is the actual consumption from the day being evaluated.
Consequently F3-G checks whether the **pipeline and fixed reference model**
can consume real price/consumption signals consistently. It does not establish
that the fixed reference BM parameters describe the real population, that
price changes caused observed demand changes, that the retrospective optimized
vector could have been known in advance, or that an objective reduction is
monetary/energy savings. Those questions require additional modelling and,
especially, parameter estimation/identification in F4.

### Observed validation and F3-G conclusion

All planned F3-G validation gates have now been exercised.

The synthetic regression suite verifies that a historical spot vector attached
as `observed_prices` is owned by the common problem, that
`evaluate_observed(...)` agrees with direct evaluation of the same fixed
vector, that fixed-input mode runs without invoking Powell, and that invalid
historical day/count inputs are rejected rather than silently truncated.

On Windows/Python 3.11 the focused historical suite passes **11/11** tests and
the complete repository suite passes **205/205** tests. The pull-request CI
independently passes the same **205/205** regression suite.

Both Powell starts succeed on all three days and the optimized 24-price vectors

F3-G is therefore **closed as a historical-input integration step**. It shows
that real hourly DK1 prices can be passed unchanged through the same F3 control
contract while preserving the existing historical calculations. It does not
show that the fixed reference BM parameters are calibrated to real consumers,
nor does it establish a causal price response or prospective tariff policy.
Those identification and parameter-estimation questions remain F4.

F3-G changes the **data/control plumbing and interpretation**, not the BM
equations, stochastic assumptions, FV scheme, mixture scheme or F3 optimizer.
